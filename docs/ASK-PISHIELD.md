# Ask PiShield

Open Intelligence → Ask PiShield. Pick a local model; select the data sources it may read; enter a question or instruction. The report source is the latest stored report, not necessarily the report previously viewed. The selected sources are gathered when you send a question and supplied to your local Ollama model. They include recorded DNS details, device aggregates, health, counters and recent visible packets. They are not arbitrary system access. Some sources may be stale or unavailable, and the Pi cannot see all network traffic. Chat history retains the last four exchanges in volatile memory and is shared by authenticated dashboard administrators. Clear it with New conversation. Deselecting a source stops new reads but does not erase past answers; clear the conversation to reset context.

Create a reusable tool by describing the desired analysis and clicking Create a reusable tool. The model proposes a name, approved data-source keys and a plain-English instruction. Review and approve before saving. Saved recipes are kept in this browser; click the name to run the recipe, or Remove to delete it. No generated program, shell command, executable, external URL, or rule change is run by the assistant. It cannot install arbitrary tools. The service uses a fixed loopback Ollama endpoint and read-only snapshots, with bounded input, context and output. The dashboard still requires authentication and a CSRF token for requests.

Both manual and scheduled reports have a new plain-language prompt. Older reports show a computed summary and their original answer in a readable text layout; originals remain accessible and exportable. AI output is not evidence by itself; investigate with DNS history and actual monitoring before making changes.
