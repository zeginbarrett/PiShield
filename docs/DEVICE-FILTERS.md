# Device filtering & privacy

Open **Filtering → Device filtering & privacy**. Select an observed or configured device, or enter its reserved IPv4 address and click Load device. Select only your intended device, never a forwarding router or the Pi itself. Existing configured MAC clients can also be selected. To avoid silently overriding subnet, hostname or MAC policies, the page refuses to create a new IP client when such policies already exist; select the applicable existing client instead.

Use Turn on for device on a filter. PiShield registers a new client when needed, preserves existing assignments, creates the required internal filtering group/list if absent, and verifies the resulting configuration through the authenticated DNS management API. You do not need to create groups manually. Turn off for device removes only that device's assignment. Existing Default/network-wide rules remain in place, and overlapping filters may still block domains. The page refuses to alter unrelated lists, shared disabled filters, or groups containing other rules. Older PiShield TV/family/gambling profiles can be reused if the exact list and dedicated group are verified; ambiguous or externally managed subscriptions stay untouched. Use the existing Lists or Domain exceptions pages for advanced policies.

After enabling a new filter, open **Update Gravity / download lists**. Test device DNS traffic in Device Privacy Monitor. Saved assignments are not proof of DNS enforcement; your device must actually use PiShield. Test streaming, sign-in and updates. No filters are automatically activated by installation. Sony Bravia, TV/ACR, vendor telemetry, data harvesting, family and gambling options are available, along with optional DNS/VPN bypass filtering. Bypass filtering may break legitimate services; keep it off unless needed and tested.

The older Filtering profiles menu is removed; native group management remains available for compatibility. The installation is a web-interface update with a backup, not a DNS database migration. It does not alter existing policies during installation. The native API and browser authentication are required. If a step fails, the UI reports the API error and refreshes actual state; a partially created group/list may remain, but clients are never assigned implicitly.
