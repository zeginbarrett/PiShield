# Privacy & data protection

Open **Filtering → Privacy & data protection**. All new filters are opt-in. Each card shows a source list, saved configuration, assigned clients, and recent exact-domain block matches. Existing lists from other policies are not changed. The default-group option applies only to clients using that group; selected-device mode requires explicit client assignments. For a TV, start with Smart TV / ACR and selected devices only. Add the TV as a reserved-IP or MAC client using Manage clients, then assign the existing client on the card. Verify the TV uses this DNS server directly, rather than a forwarding router. Review existing client selectors before creating new ones. Preserve other group memberships.

Enable the filter, choose the scope, and click **Update Gravity / download lists** to populate the list. Test streaming, sign-in, app installation, and updates. Disable the filter if something breaks, or use Domain exceptions to add an exact allow rule scoped to the intended groups. Other lists can overlap and continue to block a domain after a filter is disabled. The native settings pages allow review of existing externally owned subscriptions; the privacy page will not take them over.

The sources are [PCTestAdmin TV blocklist](https://github.com/PCTestAdmin/tv-blocklist) and [HaGeZi DNS blocklists](https://github.com/hagezi/dns-blocklists). They are downloaded by the native list manager under their own licenses. The general data-harvesting filter contains ads, tracking and other unwanted domains; vendor filters are narrower but may overlap. TikTok fingerprinting is not a comprehensive social-media blocker. DNS/VPN bypass filtering can break legitimate VPN access; keep it disabled unless you understand and test the effect. Direct IP connections, encrypted DNS and shared service domains can bypass DNS-only controls. No promise to eliminate all telemetry.

Counters examine up to the most recent 20,000 recorded gravity-blocked exact DNS queries over 24 hours and compare them to entries in the currently enabled source lists. They exclude regex and CNAME-only matches. Counts may overlap, do not establish which list caused a block, and can lag behind live DNS. The background reader has a bounded runtime and memory. No raw queries are exported.

Installation leaves existing DNS, firewall, phone notifications and privacy settings intact. The compact page layout from 1.2.2 is included. Review file-integrity changes after upgrading; do not automatically accept a new baseline. On a new Pi use the full installer. Existing 1.2 users can run `sudo bash pishield-v130.sh`.
